## 2. Durability — findings and actions

**FIXED just now — `goldberg-system` code was local-only.** Its `main` (the whole
deployed release: compose stack, reconciler config, MCP rename, charter DIR-004)
was committed but **not pushed**. I have pushed `main` and the active feature branch
to the private GitHub remote. It is now recoverable.

**OPEN — `goldberg-raw` (the immutable evidence corpus) is NOT on any remote.** This
is exactly the "no data loss" risk. Details: 5 local commits, **~6 GB** working tree,
**838 git-LFS binaries (~5.4 GB)**. The GitHub repo `goldberg-raw` exists and is
private, but has **zero branches** — the corpus lives only on the local Halob disk.
It almost certainly never completed a push because 5.4 GB of LFS exceeds GitHub's
free LFS quota (1 GB).

I am **not** silently pushing 6 GB of privileged evidence to a new/costed external
store without the client's say-so — target choice + cost is theirs. I've recommended
mirroring `goldberg-raw` to **DigitalOcean object storage** (matches the "personal →
DO" cloud rule; ~$5/mo, S3-compatible, private) and asked the client to confirm.
Once confirmed I will set up an automated mirror (git history + LFS objects) and
report an `actioned` turn here.

`goldberg-extracted` is empty (no data) — nothing to back up yet.
